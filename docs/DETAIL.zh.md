# 彻底删除会话

这个插件在会话列表的右键菜单里增加 **彻底删除会话**。它适合清理不再需要的旧对话，释放 DSH 在本机保存的会话记录占用的空间。

## 使用

1. 在左侧会话列表中右键点击一条会话。
2. 选择 **彻底删除会话**。
3. 在确认框中检查会话标题，然后点击 **彻底删除**。

取消、点击遮罩或按 `Esc` 都不会删除任何内容。

## 删除工作区及文件夹

工作区右键菜单里还有 **删除工作区及文件夹**：

1. 右键点击左侧的工作区名称。
2. 选择 **删除工作区及文件夹**。
3. 确认框中会显示完整文件夹路径，确认后递归删除该文件夹，并移除 DSH 中的工作区记录。

这个选项只删除项目文件夹和工作区注册，不会自动删除该工作区里的会话记录。内置的 **删除工作区** 仍保持原行为，只移除注册。

## 删除什么

- 整条对话的会话记录，即 DSH 持久化后端报告的该会话日志文件；
- 如果后端使用每会话一个目录，则删除该会话自己的目录（通常包含 `session.v4.jsonl.zstd`）；
- 会话在工作区中的成员关系、归档标记和置顶标记。

## 不删除什么

- `~/.dsh/attachments` 下的共享附件缓存。附件按内容寻址并可能被其他会话复用，因此本插件不会删除它们。
- 工作区中的项目文件、源码或用户文档。
- 其他会话。

## 打开中的会话如何删除

确认后，本插件会先停止该会话正在运行的任务，释放 Host 进程内的写入器，再删除会话文件；不需要退出或重启 DSH。正在生成的内容会被中断，未保存到会话日志的临时状态会丢失。

如果强制关闭失败，界面会提示“无法结束这个会话的进程占用”。此时可以重试；仍然失败时再重启 DSH 后删除。

## 安全边界

Host 端只接受同源的 `POST /api/session-delete` 和 `POST /api/workspace-delete`，并要求请求头 `x-dsh-session-delete: 1`。

- 删除会话时，实际路径来自 `sessionPersistence.stat()` 报告的 artifact location，且只允许删除与会话 ID 匹配的目录或文件名。
- 删除工作区时，路径来自 Host 端按 `workspaceId` 查到的注册记录，不接受客户端直接传入路径；只允许绝对路径的真实目录，并拒绝驱动器根目录、用户主目录、`~/.dsh` 及其子目录、符号链接和包含 `..` 的路径。

任何无法确认归属的路径都会被拒绝。

## 卸载

在 DSH 的插件管理中停用或移除 `dsh-session-delete`。已经删除的会话无法恢复；卸载不会还原它们。
